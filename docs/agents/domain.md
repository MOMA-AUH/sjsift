# Domain documentation

This is a single-context repository: the domain glossary is CONTEXT.md at the repository root, and architectural decisions are in docs/adr/.

Before exploring domain behavior, read the glossary and ADRs relevant to the task. If a referenced domain document is absent, proceed without creating a placeholder.

Use the glossary's terms in specs, tickets, code, and tests. Flag meaningful terminology gaps for domain modeling. Surface conflicts with existing ADRs explicitly, with the reason for revisiting the decision.
